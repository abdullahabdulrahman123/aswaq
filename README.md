# أسواق (Aswaq)

سوق إلكتروني متخصص في المعكرونة المعبأة — بائعين متعددين، بيع تجزئة وجملة، السوق المصري.

المستودع فيه جزئين:

- **`client/`** — الواجهة، نموذج أولي. الكتالوج المعروض لسه تجريبي في `client/src/data/catalog.ts`.
- **`server/`** — سيرفر أسواق على `MongoDB`: الأصناف بوحداتها وأسعارها (`items`)، وإعدادات البيع لكل متجر (`store_settings`).

البيانات الأساسية للنشاط التجاري (الاسم، الاختصار، الأرقام، المقرات وعناوينها) وأرقام المستخدم **مش هنا** — دي في وصلة، بطلب العميل. الواجهة بتكتبها في وصلة مباشرة، وسيرفر أسواق بيسأل وصلة مع كل طلب: مين المستخدم؟ وإيه الأنشطة اللي بيديرها؟

## السيرفر (`server/`)

كل المسارات تحت نشاط، وبتوكن الوصول اللي الواجهة خدته من وصلة:

| المسار | |
|---|---|
| `GET / POST /api/businesses/:accountId/items` | أصناف النشاط — الصنف بيتعمل على مستوى النشاط دايمًا |
| `GET / PUT / DELETE /api/businesses/:accountId/items/:itemId` | ونفسه بيشيل نسخة المتجر |
| `GET /api/businesses/:accountId/shops/:shopId/items` | أصناف المتجر ده |
| `GET /api/businesses/:accountId/shops/:shopId/items/available` | أصناف النشاط اللي لسه مضافتش للمتجر |
| `POST /api/businesses/:accountId/shops/:shopId/items` | `{ itemId }` — بيعمل نسخة من الصنف للمتجر |
| `GET /api/businesses/:accountId/shops/settings` | إعدادات متاجر النشاط (نطاق التوصيل) — لفورم المقر |
| `PUT /api/businesses/:accountId/shops/:shopId/settings` | `{ deliveryRadiusKm }` — بالكيلو، و`null` = مبيوصّلش |

`:shopId` هو **id مقر في وصلة معلّم عليه «متجر»** (`isStore`) — مفيش جدول محلات هنا، والسيرفر بيتأكد من المقر من رد وصلة زي ما بيعمل مع النشاط نفسه. إعدادات البيع بتاعته (نطاق التوصيل دلوقتي، والحد الأدنى لفاتورة الجملة بعدين) في `store_settings`: صف لكل متجر، بطلب العميل.

والمعرض **من غير توكن** — الزائر بيشوف المتاجر وأصنافها كمان:

| المسار | |
|---|---|
| `GET /api/showroom/stores` | نطاق توصيل كل المتاجر اللي بتوصّل: `[{ shopId, deliveryRadiusKm }]` |
| `GET /api/showroom/stores/:shopId` | نطاق المتجر وأصنافه: الاسم والصورة والوحدات بأسعارها الأربعة — من غير `avgCost` ولا `rate` |

قواعد مهمة:

- **الأسعار و`avgCost` بالقرش** (عدد صحيح) — نفس اتفاق `client/src/lib/pricing.ts`.
- **`avgCost` بتاع الصنف مبيتكتبش** — بيتحسب من المشتريات، والـAPI بيتجاهله لو اتبعت. أما **`avgCost` بتاع الوحدة** فبيتكتب بإيد من الفورم.
- **لازم وحدة `unitContent: 1`** في كل صنف — الكميات كلها بتتحسب بأصغر وحدة. كل الوحدات بالعدد (عدد صحيح)، وأصغر وحدة ممكن تكون دستة مثلاً.
- **`weight` بالجرام و`volume` بالسنتيمتر المكعب** للوحدة الواحدة — تحميل العربية بيقف عند أقصى وزن أو أقصى حجم (الحديد بيوصل للوزن، والإسفنج للحجم).
- **الأسعار الأربعة**: `S` في المحل و`L` أونلاين، `W` جملة و`R` قطاعي — `onSWP` جملة محل، `onSRP` قطاعي محل، `onLWP` جملة أونلاين، `onLRP` قطاعي أونلاين.
- **الاسم مبيتكررش في نفس المستوى**: فهرس فريد على `(accountId, shopId, name)`.
- **نسخة المتجر مستقلة**: الصنف بيتضاف للمتجر كنسخة كاملة (`shopId` = المقر)، مش إشارة للأصل — بطلب العميل، عشان السعر ومعدل البيع (`rate`) بيختلفوا من فرع لفرع. يعني نشاط بـ١٠ متاجر عنده ١١ صف للصنف: واحد للشركة و١٠ للمتاجر، واللي للشركة بيمثّل الشركة كلها.

منشور على Northflank من `server/Dockerfile`، جنب وصلة في نفس المشروع — التفاصيل والمتغيّرات في `DEPLOY.md` في ريبو وصلة. (`render.yaml` بتاع الاستضافة القديمة، لحد ما Render يتقفل.)

التشغيل محلياً محتاج وصلة شغالة على `5000`:

```bash
npm --prefix server install
cp server/.env.example server/.env   # وحط MONGODB_URL
npm --prefix server run dev
```

## ما يعمل فعلاً في النموذج

- **الصفحة الرئيسية (المعرض)**: المتاجر من كل الأنشطة — مقرات وصلة المعلّم عليها «متجر» (`GET /api/stores` في وصلة)، وبتظهر حتى للي مسجّلش دخول. كل متجر باسمه واسم نشاطه، ولوجو النشاط أو اختصاره
- **مكان المشتري**: من «عناويني» (في وصلة)، أو «موقعي الحالي»، أو نقطة من الخريطة — وبيتفتكر على الجهاز. بيه المتاجر بتترتب من الأقرب (خط مستقيم)، وكل متجر عليه المسافة وبيوصّل لمكانه ولا لأ. من غيره: الأحدث الأول
- **صفحة المتجر**: كروت الأصناف — الصورة والاسم، واختيار الوحدة والسعر بتاعها، والكمية بزرارين (+) و(−) وتتكتب باليد (أرقام صحيحة بس). فوقهم «استلام من المتجر / توصيل»، والتوصيل متاح بس جوه نطاق المتجر. السعر: الشركة جملة والشخصي والزائر قطاعي، والاستلام بسعر المحل والتوصيل بسعر الأونلاين — من غير كلمة جملة ولا قطاعي
- **نطاق التوصيل** في فورم المقر (لما يبقى «متجر»)، بيتحفظ في أسواق. فاضي = المتجر مبيوصّلش
- **«عناويني»** في «حسابي»: إضافة وتعديل ومسح، بنفس فورم عنوان المقر
- تصفح الكتالوج، البحث، الفلترة بالشكل والماركة والوزن والبائع، والترتيب
- **التبديل بين حسابك الشخصي وأنشطتك** من خانة «حساباتي» في المنيو اللي في صورتك فوق — الشخصي قطاعي والنشاط جملة، والأسعار كلها بتتغير فوراً (الكلمتين دول مبيظهروش للمشتري نفسه، بطلب العميل)
- **شرائح أسعار الجملة**: السعر ينزل تلقائياً لما الكمية توصل لحد الشريحة، مع تنبيه "زوّد كذا توفّر كذا"
- **إدارة أصناف المتاجر** (من المنيو): تختار متجر من مقرات النشاط، وتختار صنف من أصناف الشركة بكومبو فيه بحث، وتدوس «إضافة» — الصنف بينزل في ليستة أصناف المتجر تحت. الصنف اللي اتضاف مبيظهرش تاني في الاختيار، وينفع يتشال من المتجر من غير ما صنف الشركة يتأثر.
- السلة مع حساب الحد الأدنى للطلب والشحن المجاني، محفوظة في localStorage
- وضع فاتح وداكن

## ما لم يُبنَ بعد (بانتظار قرارات العميل)

| البند | القرار المطلوب |
|---|---|
| صفحة الدفع | طرق الدفع المعتمدة (أونلاين / عند الاستلام) |
| حسابات المستخدمين | التسجيل، واعتماد حسابات التجار، والمستندات المطلوبة |
| لوحة البائع | ما الذي يملكه البائع: منتجاته، أسعاره، مخزونه؟ |
| لوحة الإدارة | الأولوية المعلنة من العميل — لم تُبنَ بعد |
| حساب الشحن | حالياً سعر ثابت. المفترض حسب المحافظة والوزن |
| نموذج العمولة | نسبة؟ اشتراك؟ لم يُحدَّد |
| تقسيم الطلب | طلب فيه منتجات من بائعين مختلفين — شحنة واحدة أم أكثر؟ |

## القواعد التجارية المبدئية

في `client/src/data/catalog.ts` تحت `rules` — كلها أرقام مؤقتة للعرض ومحتاجة تأكيد العميل:

- الحد الأدنى للطلب: 300 ج.م
- شحن مجاني فوق: 750 ج.م
- شحن ثابت: 45 ج.م

الحد الأدنى للطلب تحديداً ليس تفصيلة تجميلية: المعكرونة منتج رخيص وثقيل، وتكلفة شحن الطلب الصغير قد تتجاوز هامش الربح عليه.
